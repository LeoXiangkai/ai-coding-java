# Git 提交与 worktree 收口

## 分支边界

AI 只在任务分支工作，只合并和推送项目声明的基线分支。基线名称从项目 `AGENTS.md`/`CLAUDE.md` 或 `branch.<task>.baseline` 读取，不写死。`main`/`master` 由用户在代码托管网页合并；若项目声明基线就是 `main`/`master`，推送前必须先取得用户确认。任务分支默认不推送。

只读检查可用 `git`；写操作优先使用组件提供的 `<claude-home>/bin/git-safe`。不要删除 lock 文件、使用 `--no-verify` 或把无关改动带入提交。

## 提交流程

1. 确认当前 worktree、任务分支、基线分支、主工作区路径和工作区状态；基线不明确时停止并记录待确认项。
2. 查看完整 diff、最近提交格式和变更范围。新文件名与提交信息不得包含临时任务序号、缺陷号、工单号或测试编号。
3. 按受影响项目层执行必要编译/测试；未验证内容写明原因。逐个文件暂存，不使用 `git add -A` 或 `git add .`。
4. 提交信息说明业务原因、变更和验证；不写任务身份。提交后重新检查状态与提交内容。
5. worktree 收口时确认主工作区位于声明基线且干净，记录任务分叉 SHA 和合并前基线 SHA；按项目要求拉取基线，使用受控的 `--no-ff` 合并。冲突停止，交由用户手工解决。
6. 调用 `scripts/post-merge-verification.sh` 做合并后判定，再按输出执行跳过或一次定向回归；不得把 `RUN_TARGETED` 当作通过。
7. 仅在基线允许、用户已授权且验证完成时推送；完成后报告提交、分支、验证结果和未覆盖项。

## 合并后验证门禁

脚本输出 `SKIP_DUPLICATE` 的前提是：来源已持久化、任务分叉与合并元数据有效、受控 `--no-ff` 合并、无冲突/手工改写，且任务分叉至合并前没有其他任务分支的 first-parent 合并。以下任一情况输出 `RUN_TARGETED`：检测到其他任务合入、来源不明、SHA 无效、合并方式不受控或手工解决冲突。定向回归只覆盖受影响范围；用户明确要求时才跑全量。

脚本失败安全：缺参数、仓库不可用、分支关系不成立都返回 `RUN_TARGETED` 并说明原因。脚本不联网、不修改仓库。
