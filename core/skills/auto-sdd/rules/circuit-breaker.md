# auto-sdd · 护栏与自适应熔断（冷层，判"该停了"时加载）

> 主文件只留指针。当要判 budget 超标、是否熔断、回滚时加载本文件。

## 护栏

- 每轮起手 `mvn compile -pl <module> -am` 冒烟;坏了本轮只修不加功能
- **单 goal 预算分两档,超标必拆或必记账(禁静默超标)**:
  - **降级 goal(外部执行体不可用,改派子代理)**:≤300 行 / ≤8 文件(强护栏);超了**拆下一 goal**(不是停)。主会话不自编 goal(`rules/executor-handoff.md §规则 1`)
  - **外部执行体 goal(单写者 + 主会话 diff 审查 + 独立核实兜底)**:按**单一业务域**聚合放宽(经验上限 ≤1 域 / ≤25 文件;切太碎反贵),仍受熔断 diff 信号约束
  - 任一档**超上限**:要么拆 goal,要么 append `{"goal":"Gx","status":"note","evidence":"budget-breach:N行/M文件,理由<为何不可拆>,兜底=主会话 diff 审查+独立核实"}`——**护栏不许 decorative,超标无痕=跑偏**(实证:两个项目均出现单 goal 超千行且账本 0 记录)
- 跨 session / 压缩:**resume-first** 读 `06-ledger.jsonl` 最后状态续跑。**resume = 起新 session 只注入账本 evidence,不继承失败 transcript**——同一问题纠错 ≥2 次后,干净重开优于续脏上下文(长 session 累积失败上下文反而劣化)

## 自适应熔断(不写死 N —— 写死全局迭代数会混淆"任务规模 vs 卡死")

判"该停了"用三层信号,**主力是进度 + 预算,计数只兜底**:

1. **token / 成本预算为主**:调用方给定本次上限(或 budget directive);**按花费熔断**而非按次数。超预算 → 转人工。
2. **进度信号做主力(任务无关,自适应)**:命中任一即卡死 → 转人工——
   - 同一 bug 签名**连续 ≥3 次**:签名落地为 `{失败用例集合 + 拟改文件集合}` 的哈希,连续相同即卡死(比靠 LLM 自报"我在重复"客观)
   - 失败用例**集合连续不变**(看集合 diff,**不只看数量**——防"修 A 破 B、总数不变"的振荡骗过计数)
   - **振荡**:修 A 破 B、修 B 破 A 往返 ≥2
   - **有效迭代门**:LLM 无外部信号的自我纠错是负收益。**没让外部测试由红转绿的迭代不计入"进度"**——只有外部断言结果改善才算一次有效推进,否则视同空转(避免内在自纠伪装成"在推进")。
3. **per-goal 计数随规模 scale,仅硬兜底**:每 goal 迭代上限 = 随该 goal 行为单元数放大的**宽松**值,只防真跑飞,不误伤正常长任务。**不设全局总迭代写死数**。但配一条**下限门**:goal 必须真通过本地自测 + 主会话 diff 自审 + 审查判档（低风险可为 `skip`）才允许标 `complete`(LLM 过度自信会过早收手,缺下限同样致命)。

**内循环 vs 外循环强度不同**:
- **内循环(STEP1-2,无人值守)**:三层全开,这是自驱烧 token 的地方,强熔断。
- **外循环(STEP4 e2e)**:每轮复测要重新触发提测+部署(自驱但节奏慢),从轻——但**提测与部署自驱(按项目约定)、不靠手工提测当人肉刹车**:同一 e2e bug 复现 ≥3 次照样按熔断转人工(human-review gate ON 时收口闸是人的检查点)。

熔断动作:**先回滚到 last-good checkpoint,再转人工 + 写 `iteration-halt-report`**。over-refinement 会把对的改错(测试覆盖单调下降)——**别在劣化轨迹上留代码**,熔断时回退到账本标记的最后绿色 commit——**`last_good_commit` 是熔断回滚的唯一锚点,gate-design / gate-local / 每个 `complete` 行都必须带它(sha),不是可选 prose;实证:两项目 ledger 全程 0 条 `last_good_commit` → 熔断真触发时无可回退点,锚点必须随 gate 落地**。报告含:触发哪层信号 / 失败用例集合 / 最近 N 轮 diff / last-good commit / 建议人工先看哪个文件,**不静默失败**。
