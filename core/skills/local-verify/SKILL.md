# 本地验证

## 路由

读取项目声明和文件后选择：

| 探测 | 路由 |
|---|---|
| `pom.xml` / `build.gradle*` | `java-verify` |
| `pyproject.toml` / `requirements*.txt` / `setup.py` | `python-verify` |
| `package.json` 含 Vue 依赖 | `vue-verify` |

若对应语言包未安装，执行项目声明的最小构建/测试命令并明确降级原因；不要假设框架、模块、端口或凭据。项目和命令名比较先 trim 并做大小写归一；缺失、空值或空白配置必须先报出并停止该步骤。

## 验证顺序

1. **开发自验**：按项目声明执行改动模块的单测和增量编译，阅读完整计数；检查 `git diff` 的逻辑、副作用、异常路径和集成完整性。
2. **启动服务**：从项目声明或启动配置读取入口、环境变量、profile、JVM/运行参数和输出日志路径。启动前检查监听端口；若端口被占用，先报告进程信息并按项目授权流程处理。后台启动后轮询日志和监听状态，成功信号包括应用启动完成或端口已监听；失败信号包括上下文初始化失败、绑定冲突、非零退出和未捕获异常。进程和临时日志句柄必须在验证结束后释放。
3. **接口级自测三步法**（新增/修改 Controller、VO、Mapper SQL 或相关 bug 必须执行）：
   - 起服务：确认实际进程、配置和就绪日志。
   - 取真实数据：使用项目声明的数据库工具查询一条符合前置条件的开发/测试数据；不造 mock，不直接改业务状态；查询结果先核对行数、null/blank 和字段类型。
   - 真实请求：用 `curl` 请求改动接口，核对 HTTP 状态、业务码、响应字段与数据库值；记录脱敏请求、响应和查询证据。返回空、字段缺失或非预期状态都算失败。
4. **日志检查**：按配置定位日志，不扫描整个工程。提取 `ERROR`、异常堆栈、关键 `WARN`，按根因去重；若有 traceId/requestId，关联同一请求的入口、错误和结束日志。大日志只取最近窗口并记录时间范围。修复后做差集：已消失、仍存在、新增三类分别报告；不得调低日志级别、删日志或 catch 后吞异常。
5. **集成冒烟**：按项目声明跑关键流程，观察异步任务、消息、缓存和数据库实际结果。无法真实验证的项目依赖标记 `BLOCKED`，不写成 PASS。

## 失败与复测

失败先稳定复现并记录原始输出、最小复现、已排除假设和根因判据。修复后至少复测失败项、共享同一 Controller/Service/Mapper/VO 的相邻项和改动模块单测；不得放宽断言、换容易通过的数据、改配置绕过失败或跳过测试。

## 输出

报告必须分开写：已完成的单测/编译、启动与日志证据、真实接口/数据库证据、未覆盖与 `BLOCKED`、需要测试环境继续验证的内容。测试命令输出必须包含实际计数（通过、失败、错误、跳过）；只有退出码没有计数时不得声称已验证。
