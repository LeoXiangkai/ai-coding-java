# 执行体交接规则

## 执行体

- **外部执行体**：无头 CLI（如 `claude -p`、`codex exec`），在指定 worktree 内完成编码、构建与自测；是否可用、用哪家模型由本机适配决定，本规则不绑定具体实现。
- **子代理**：当前会话内派出的 `dev` / `qa` / 语言专项角色。
- **降级**：外部执行体不可用（未安装、非零退出、拿不到凭据）→ 该任务改派中档模型子代理，汇报中标明"因外部执行体不可用降级"，不询问、不挂起。

## 规则 1：按「风险档 + 预计工具轮数」选执行主体，不按行数

先看风险，再看轮数——命中高风险即 C，轮数少不作豁免。

| 档 | 判据 | 执行主体 |
|---|---|---|
| **C** | **改动对象是业务代码或测试代码**，且命中任一高风险信号：新模块 / 新增对外接口 or 新表 / 改已有契约 / 跨模块 / 跨进程 / PII·权限 / 核心引擎 / 新增测试类（探针类·e2e 脚本·新回归套件）。配置·规则·文档·脚本·hook·CI 编排**不入 C 档**，按轮数判 A/B | 外部执行体（高档模型） |
| **B** | 零高风险 **且** 预计 **≥5 轮**工具调用 | 外部执行体（中档模型） |
| **A** | 零高风险 **且** 预计 **<5 轮**收口（≤5 行业务码 / typo·日志级别·import·注释 / 已有方法补一句守卫） | 主会话直接 Edit |

**预计轮数速算**：定位 1-2 + 每个待改文件 1 + 依赖/构建/验证 2-3 + 提交收口 2-3。改 3 个文件并跑一次 build 已 ≥10 轮，属 B。多文件"纯样式/纯机械"改动是典型低估形态。

**派工前契约必须冻结**（B/C 同）：看图确认、口径歧义、方案分叉、要问用户的选择，主会话先解掉再派——执行体问不了用户。切法：主会话定位+消歧+冻结改法 → 执行体编辑+构建+自测 → 主会话 diff 自审+裁决+收口。

## 派工方式（硬约束）

- 外部执行体以后台任务启动，工作目录必须是 worktree 路径（`rules/worktree-management.md`），禁止指向主工作区。
- **派完就等回调，禁止轮询**；唯一例外是怀疑挂死时**一次性**确认。
- 执行体只加载它自己的配置与仓库内项目入口文件，**不加载主会话的编排类规则**；任务相关的契约、路径、禁改范围必须写进 prompt。
- 执行体不得再派子代理、不得 commit / push。
- 并行多个执行体前确认写集互斥、共享环境（端口/数据库）不冲突；任一不满足即串行；并发数受 worktree 上限约束。

**prompt 必带**：任务目标 / worktree 绝对路径 / 已冻结契约与基点 / 允许与禁止修改的路径 / 独立验证命令（编译、相关测试）/ 返回内容（实际改动文件、逐项执行结果、命令与退出码、证据位置、已知风险）/ "不得调用代码审查 skill、不得再派子代理"。

## 规则 2：prompt 末尾固定追加边界清单

```
实现时顺手排查,需要防御的本轮处理,不留给后续审查:
- 字符串比较: trim / equalsIgnoreCase / 大小写归一
- null / empty / blank 守卫
- 集合迭代 ConcurrentModification 风险
- 异常是否被 catch 后吞掉
- 资源(连接/流/锁) 是否释放
- @Transactional / @Async 调用链是否经过 Spring 代理
- Python: 可变默认参数(def f(x=[])) / 裸 except 或 except Exception: pass / with 管理文件与连接
- Vue: 解构 reactive / props 丢失响应式(用 toRefs / computed) / watch·定时器·事件监听在 onUnmounted 清理 / v-for 的 key 不用 index
- 不得修改断言 / 删测试 / 跳过测试制造通过
- 只改任务需要的行: 不顺手重构 / 格式化 / 删注释 / 改无关测试; 发现的无关问题写进返回内容,不在本轮改
```

## 规则 3：审查点批处理

多个问题一次性全列给执行体，不"改一个看一个"。只发现 1 条且属 A 档 → 主会话自己改。

## 「复用既有实现」型指令：派工前先验证被复用的实现是对的

prompt 里出现「与既有 X 同源 / 参照 X 写法 / 复用 X」时，先对 X 走一次三段式（`rules/context-engineering.md`），读 X 的 SQL / 实现体而非方法名与注释，核验结论写进 prompt。X 有问题 → 先修 X。否则执行体会忠实复制缺陷，并带着"与既有一致"的外衣通过审查。

## 职责分工

主会话负责设计、准备和裁决；执行体负责实施、执行和采集原始证据。不做"两边都跑一遍"的纯重复。

**测试交接三阶段（固定顺序）**：① 主会话冻结行为预期 / 归属层 / 步骤 / 成功判定 / 证据要求，并备好可直接执行的数据 → ② 执行体按方案实施 + 完整执行 + 返回原始证据 → ③ 主会话审查实现质量与证据强度后裁决 PASS / FAIL / BLOCKED。

### 主会话硬门禁（常驻）

- **diff 自审**：每个最终可合并 change-set 合入基线前，逐过逻辑正确 / 副作用（事务·缓存·锁·线程·日志）/ 异常路径（null·空集·超时·并发·登录态）/ 周边集成（调用链·命名·权限习惯）/ 注释与解释性文字（按 `rules/context-engineering.md §产出侧` 逐条问「删掉它，读者会做错什么」）/ **夹带**（每行改动须能追溯到本次需求；顺手重构·格式化·删注释·改无关测试一律回退），结论写进汇报。是否另派独立 reviewer 按实际 diff 风险判定。编译通过 ≠ 审查通过。
- **测试设计与数据准备**：派工前完成三阶段第 1 步，不把需求澄清或找数据转嫁给执行体。
- **裁决权**：审断言、mock、异常路径、层级与证据真实性；PASS / FAIL / BLOCKED 一律由主会话判定。
- **DDL / 数据脚本自行执行**到开发与测试环境并确认已应用（生产除外）。
- **合并后验证**按 `rules/git-workflow.md §合并后验证门禁`；定向检查不得冒充全量回归，compile 不得冒充业务回归。
- **不通过放宽断言 / 跳过测试 / `-DskipTests` 制造"通过"**。

### 代码审查单元

以 repository root + 同一 worktree 当前分支 + 不可变 fork-oid 标识的最终可合并 change-set 为单位。同批 finding 一次汇总、一次返工、统一复审；reviewer 不得再派子代理或调用审查 skill。

## 执行体汇报必独立核实

执行体（背后可能是第三方模型）与子代理的 summary 是"它想做的事"，不是"它真做了的事"。**执行体自报的模型名不可信**，实际上游以执行体自身的调用日志为准。

| 声明 | 核实动作 |
|---|---|
| "全量测试跑不过是既有基线问题" | `git log -p <失败文件>` 看修改是否早于本次，或 checkout 基线独立跑 |
| "编译通过" | 独立跑变更模块的编译（如 `mvn compile -pl <模块> -am -DskipTests`、`vue-tsc --noEmit`、`python -m compileall`） |
| "单测覆盖 X 场景全绿" | 读方法名 + 断言内容，判是否真覆盖（常见空断言 / 只验 mock 被调用）；多模块 `mvn test` 必须带 `-am` |
| "DDL 与主表字段严格对齐" | diff 字段定义（类型·长度·NULL·comment） |
| "已符合设计约束" | 对设计文档每个约束条目 grep / 读取核对 |
| "边界限制，无法实现" | 验证技术路径是否真不可行再决定接受 |
| "测试没往共享库留残留" | 按测试专属标记查 = 0 + "本次新列字段非空 = 0" 旁证；**禁用计数差** |

汇报给用户时区分"执行体声称 vs 主会话核实"。
