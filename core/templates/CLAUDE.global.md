# ai-coding-java 全局入口

> 由 `aicj install` 安装到 `~/.claude/aicj/CLAUDE.global.md`，并经 `~/.claude/CLAUDE.md` 标记块引用。

## 1. 单一事实源

优先级（前者覆盖后者）：**用户指令 > 项目 `CLAUDE.md` / `AGENTS.md` > 本文件 > `rules/*` > `refs/*` > `agents/*`**。

- 同一规则只保留一个权威位置，其他文件只引用，不复制。
- 不引用本机不存在的 skill、agent 或工具；标"若已安装"的能力缺失时按文中替代做法执行。

## 2. 改动分级（T0–T3）

按改动的**客观信号**判档，避免小改动走重流程，也避免高风险改动被"就几行"低估。

| 档 | 触发信号 | 走什么 |
|----|---------|--------|
| **T0 直接干** | ≤5 行业务码且零高风险；或纯文档/配置值/注释/日志级别/import/格式 | 预计 <5 轮工具调用时主会话直改（仓库文件先走 worktree）；≥5 轮按 T1 外派 |
| **T1 轻改** | 单模块/单域内、≤50 行、不碰任何高风险信号 | worktree → 执行体编码 → diff 自审 → 本地自测 → 提交 |
| **T2 中改** | 改**已有**对外接口/契约（VO·SQL）、核心逻辑、高回归、触 PII/权限、同域 2-3 文件 | TDD（核心算法/契约）+ 局部设计 + 契约层真数据验证（`rules/context-engineering.md §3.5`）+ 执行体 + diff 自审 + 按风险独立审查 |
| **T3 完整流程** | 新模块/新业务域、**新增对外接口 or 新表**、跨模块、跨进程（MQ/定时/第三方）、状态机>3 态、多角色/影响面大 | 完整设计（需求→设计→测试归属→实现→本地自测→提测）+ 执行体 + 独立审查；入口 skill：add-module（有人驾驶）/ auto-sdd（自驱） |

**高风险信号**（命中任一即上浮）：新对外接口 / 新表·字段 / 契约改（字段名·类型·前后端口径）/ PII·加密 / 权限·越权（IDOR）/ 跨模块 / 跨进程 / 状态机>3 / 核心引擎。

- 🔺 **红线上浮**：命中高风险信号直接 ≥T2，**行数少不作豁免**。"就几行/机械镜像"是最常见的低估陷阱。
- 🔻 **纯机械下沉**：行数大但纯机械（rename/move/格式化/镜像已有模式）且零高风险 → 可降一档，仍外派执行。
- ⏱ **轮数否决行数**：执行主体以 `rules/executor-handoff.md §规则 1` 为准。
- 用户明确要"完整/仔细/先设计" → 直接 T3。

**判定顺序**：纯文档/配置/≤5 行零风险 → T0；命中高风险 → 新域/新接口/新表/跨模块/跨进程/状态机>3 = T3，其余 = T2；否则单域 ≤50 行 = T1；拿不准往高一档靠，但别一律拉满。

## 3. 术语约定

- `本地自测` = 本地编译/单测/联调/启动检查/局部验证
- `测试环境验证` = 提测后服务/链路/日志/依赖验证
- 不允许笼统说"测试"

## 4. 角色边界

PM / SA / Dev / QA / Scanner 职责见 `agents/*.md`。核心约束：

- Dev 描述的是"职责"而非"执行人"，执行主体按 §5 判定
- QA 不通过降低断言、跳过测试制造"通过"

## 5. 执行主体

由 `rules/executor-handoff.md §规则 1` 判档，判据是**预计工具轮数 + 风险信号，不是行数**：

- **A 档**（零高风险且预计 <5 轮）：主会话直接改
- **B 档**（零高风险且预计 ≥5 轮）：cc 用 Claude Code 子代理，worker 先用外部执行体，失败再降级子代理（中档模型）
- **C 档**（命中高风险信号）：cc 用 Claude Code 子代理，worker 先用外部执行体，失败再降级子代理（高档模型）
- 主会话只做**编排 + diff 自审 + 按风险独立核实 + 收口**，B/C 档不回退成主会话直编
- **派工前先冻结契约**：口径消歧、方案分叉、要问用户的选择，主会话先解决再派

横向纪律（三档都适用）：任何逻辑改动由主会话做 diff 自审并在汇报中带结论；生成的 DDL / 数据脚本自行执行到开发与测试环境（生产除外）；改完默认跑一次实际效果自测；不盲信执行体 summary，区分"执行体声称 vs 主会话核实"；按风险门控的独立代码审查走 `code-review` skill（随组件安装，未装则主会话自行按同等深度审查）。

### 5.1 子代理档位

| 档 | 判定信号 | 委派对象 | 模型 |
|----|---------|---------|------|
| H 机械 | 批量检索 / 文件清单 / 日志解析 / 正则提取 / diff 摘要 / 静态扫描；零跨文件推理 | `scanner` | 低档 |
| S 常规（默认） | 单模块编码 / 局部 bug / 单测 / 常规调试 / 文档；≤5 文件依赖 | `dev` / `qa` / `pm` | 中档 |
| O 攻坚（例外） | 跨 ≥10 文件重构 / 架构设计 / 领域模型变更 / 疑难 bug / 性能根因 / 安全审计 / 多方案取舍 | `sa` | 高档，派工须写明"为什么中档不够" |

- 边界模糊保守落 S；批量扫描一律 H，禁止升档；O 连续最多 2 轮，第 3 轮起回 S。
- 派工说明带档位标记 `[H]` / `[S]` / `[O]`；用户显式指定模型时以用户为准。

### 5.2 成本纪律

成本 ≈ **轮数 × 平均上下文大小**，模型档位只影响其中一小部分。

1. **并行发起无依赖的工具调用**：一轮 N 个 = 1 轮成本，串行 = N 轮；零质量风险，纯赚。
2. **纯检索不在主会话做**：grep / 文件清单 / 日志解析 / 字段抽取外派 `scanner`。
3. **子代理 prompt 是乘数不是加数**：只写目标 / 路径 / 已冻结事实 / 禁改范围 / 返回格式，不铺陈背景。
4. **同形状的批量往返压成一个脚本**：同一类查询 / 探测 / 校验 **≥5 次 → 必须脚本化**，只回收汇总结果。

外派阈值：预计 ≥5 轮且任务可完整描述 → 外派；需现场建立判据的（测试设计、结果裁决、口径冲突、架构决策）不外派。一件事做完就开新会话，比被动压缩上下文便宜。
