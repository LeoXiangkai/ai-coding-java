# Java 本地自测

按证据顺序执行，不把编译通过当作验证完成：

1. **探测**：运行 `scripts/detect_java.py <project_dir>`，记录构建工具、wrapper、模块、版本、命名空间、持久化框架和生成命令。
2. **静态检查**：对改动文件运行 `scripts/static_review.py <paths...>`；先处理 P0，再处理 P1。没有发现不等于已覆盖运行时行为。
3. **编译**：按探测结果执行 Maven 或 Gradle。多模块使用 `-pl <模块> -am`（Gradle 使用对应模块任务和依赖模块）。
4. **相关单测**：只跑受影响模块及相关测试；Maven 多模块命令必须带 `-am`。不得用 `-DskipTests` 代替单测。
5. **启动与日志**：Maven 多模块的 `spring-boot:run` 不带 `-am`，依赖模块需先 `install` 到本地仓库；启动实际应用，看到 `Started .* in` 才记为启动成功；同时扫描 `ERROR`、`Exception` 和异常堆栈，解释或修复每一项。
6. **接口改动**：用真实开发/测试数据 curl 至少一次接口，记录状态码、关键响应字段和数据来源。没有真实数据时明确写未验证。
7. **汇报**：分别列出探测、静态检查、编译、单测、启动日志、接口和未覆盖项的命令、退出码与证据。

若已安装，可引用组件内的 code-review skill 或其他 agent；未安装时降级为本 skill 的清单和人工复核，不把引用能力当作验证证据。

## 代理与事务复核

涉及 `@Transactional`、`@Async`、`@Cacheable`、锁、连接池或异步任务时，额外确认调用经过 Spring 代理、受检异常回滚、事务内异常未被吞掉、线程池和锁/连接资源在成功与失败路径都释放。
